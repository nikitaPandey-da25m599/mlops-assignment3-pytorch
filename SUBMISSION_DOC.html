3. Implementation Write-up (~400 words)

What I Built

For Assignment 3 of the IIT Madras M.Tech MLOps course, I designed and implemented a complete end-to-end MLOps pipeline for training and serving a PyTorch image classifier on CIFAR-10. The project covers the full production lifecycle: a custom CNN model, Docker containerisation, Kubernetes orchestration, GitHub Actions CI/CD, and a structured Git workflow with feature branches and pull requests.

Model & Training

I implemented a CIFAR10Classifier — a three-block CNN using PyTorch's nn.Module, with BatchNorm2d, ReLU, and MaxPool2d at each stage, followed by an adaptive average pooling layer and a fully-connected head (512 → 256 → 10). The training loop uses the Adam optimiser with ReduceLROnPlateau scheduling and early stopping after five epochs with no validation-loss improvement. The best checkpoint is saved to a configurable directory.

Docker

I used multi-stage builds (builder stage for pip install, slim runtime stage) to keep the final images lean and production-safe. The training image is based on python:3.11-slim with CPU-only PyTorch 2.1.0; the serving image runs a FastAPI endpoint on port 8080 with a /health check. Both images run as non-root user mluser.

Kubernetes

For orchestration I created a complete Kubernetes stack: a dedicated namespace, a ConfigMap for training hyperparameters, a PersistentVolumeClaim (ReadWriteOnce, 5Gi) for the model checkpoint, a Job (with backoffLimit=3) for training, a 2-replica Deployment for serving with liveness and readiness probes, a ClusterIP service, and a HorizontalPodAutoscaler that scales between 2 and 10 replicas at 50% CPU utilisation. Using a Job rather than a Deployment for training reflects how batch ML workloads actually behave in production.

CI/CD

The GitHub Actions pipeline runs on every push: it checks code style with flake8 and black, executes unit tests with pytest (6 test cases covering forward pass, dataset transforms, and serving endpoints), and performs a docker build --no-cache dry run to catch broken Dockerfiles early.

Challenges Faced

  • Corporate network (Zscaler) blocking HTTPS pushes to GitHub: I resolved this by generating an SSH keypair and configuring ~/.ssh/config to use SSH instead of HTTPS. This itself was an MLOps infrastructure lesson — enterprise network policies are real constraints.
  • PVC ReadWriteOnce conflict: The training Job and serving Deployment cannot share a ReadWriteOnce PVC simultaneously on a single-node cluster. I addressed this in the YAML notes and would use ReadWriteMany (NFS/EFS) in a real cluster.
  • Default branch naming: Git initialised with master while GitHub expected main. Fixed by running git branch -M main before the push.
  • Docker image size: Initial single-stage builds were ~1.8 GB. Multi-stage builds reduced this to ~600 MB for the training image and ~400 MB for the serving image.
